# Security Policy

## Reporting a vulnerability

Please do not post sensitive exploit details, private keys, credentials, tokens, personal information, or console-identifying data in public issues.

For reports that may affect users or expose a security weakness, contact the maintainer privately first when possible. Include only the minimum information needed to reproduce the issue safely.

Public bug reports should focus on observable behavior, affected firmware/version, logs with private information removed, and reproducible steps that do not disclose unrelated secrets.

## Release integrity

Public release notes must distinguish between:

- hardware-confirmed behavior;
- static/build validation;
- experimental or unverified behavior.

A static test or successful build must not be described as hardware confirmation.
