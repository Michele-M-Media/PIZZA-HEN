PIZZA HEN R7.5 — CHEATS TOOLBOX DIRECT + DEBUG LEGACY OVERLAYS OFF

Base:
- R7.4 feature set preserved.
- R7.2 hardware-PASS boot/KStuff lineage preserved.
- Debug Services Media bridge remains byte-frozen: PZHN00002 -> original v0.1 launcher -> /hbldr -> pizzahen-toolbox-open.elf.

Problem reproduced from hardware video VID_20260818_131019.mp4:
1. ★ PIZZA HEN Cheats was inserted by the resident Game Options service, but its action URL was still etaHEN?Cheats_not_open. That URI is consumed only after the full Debug Services ShellUI hook set is injected. Therefore Cheats incorrectly depended on Debug Services and could reach a native cheat page with no valid TID.
2. Full Debug Services LoadSettings() could restore persisted etaHEN/ShellUI overlay flags and /system_tmp/fps_enabled, making the old CPU/GPU/FPS/IP/KStuff overlays appear again.

R7.5 repair:
- OptionMenu/createJson keeps the existing ★ PIZZA HEN Cheats insertion but changes only its target to the owned web Toolbox:
  http://127.0.0.1:8080/fs/data/PIZZA_HEN/ui/toolbox-launcher.html?tid=<TITLE_ID>&pid=<LIVE_PID>#cheats
- No Debug Services URI or Boot hook is required for this action.
- The modern Toolbox Cheats page now calls the existing etaHEN/PIZZA util ABI only:
  BREW_UTIL_GET_GAME_VER  0x08000009
  BREW_UTIL_GET_GAME_CHEAT 0x0800000A
  BREW_UTIL_TOGGLE_CHEAT   0x0800000B
- The existing util backend remains the authority for version lookup, cheat cache parsing and cheat toggling. R7.5 adds only a web/API transport surface around those existing commands.
- If the game is not running, cheats can still be displayed but toggle switches remain disabled, matching the existing native behavior.
- During full Debug Services injection only, legacy ShellUI overlay flags are forced OFF and /system_tmp/fps_enabled is removed.
- The separate PHU Overlay payload and /data/phu_overlay.lock are NOT touched.
