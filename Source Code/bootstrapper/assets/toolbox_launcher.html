Fan Target

Due implementazioni separate. PIZZA HEN non modifica i payload: quando ne attivi una, ferma l’altra per evitare che due daemon riscrivano contemporaneamente la soglia della ventola.

Opzione 1 — fan_target 0.1
Target Temperature85 °C è il valore consigliato dal progetto se non sai quale scegliere. Un target più basso fa reagire prima la ventola.
Fan Target — Opzione 1Comportamento esistente invariato: ON avvia uno dei cinque ELF fan_target 0.1 (65/70/75/80/85 °C).
Opzione 2 — ps5-fan-control v0.3
Temperatura obiettivo — Opzione 2Imposta direttamente target_temperature del fan_control.ini originale: da 30 a 90 °C. Non è una percentuale fissa della ventola: il driver PS5 continua a regolare automaticamente la velocità.
PS5 Fan Control v0.3ELF originale di owendswang. Legge prima /mnt/usb0…usb7/fan_control.ini, poi /data/fan_control.ini; senza config usa 70 °C. ON usa il valore impostato sopra e avvia il daemon originale. Il daemon rilegge periodicamente fan_control.ini, quindi puoi cambiare il target anche mentre è attivo.
PIZZA HEN modifica solo /data/fan_control.ini (target_temperature, in °C) e non il payload. Un fan_control.ini presente su USB mantiene la precedenza prevista dall'ELF originale. L'ELF v0.3 resta byte-identico al file fornito.

PoorDS4

PoorDS4 0.1.0-rc38 by ItsBlurf. Original upstream release payloads, embedded and deployed byte-for-byte without binary modification.

Automatic wireless DS4 bridge — RC38Pairs with a wireless DualShock 4 already connected to a logged-in PS5 user and follows native PS5 game launches. Upstream requires one automatic instance only.
Read-only status snapshotRuns the original PoorDS4-status.elf and then shows /data/poords4/game-pad-bridge-status.txt without interpreting or rewriting it.
Cooperative stopRuns the original PoorDS4-stop.elf. It creates the upstream stop request; the running bridge performs its own cleanup.
RC38 is experimental. Upstream live-tested firmware is 11.60; 8.60 and 12.40 have exact manifests, while other firmware is structural-admission only and hardware-unverified.
No status snapshot requested.

Upstream behavior: PoorDS4 cleans up before rest mode and exits; reinject it after wake. The project also recommends saving game progress before testing experimental builds.
